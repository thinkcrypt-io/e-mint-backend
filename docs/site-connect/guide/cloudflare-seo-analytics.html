About the addresses in this guide. MINT_API stands for your Mint API address and mint_pk_xxxx for your project key. Don't type them by hand: copy the ready line from Website setup → Existing website in your project. It has both filled in.

1. How it works

A site built anywhere (WordPress, Webflow, a hand-written HTML site, a React app, a site an agency made) becomes a Mint website project. You edit each page's SEO in the panel under Website → SEO and see visitors under Analytics. You don't edit the site again: changes show on it within a minute.

The pieces

PieceWhat it does
Website → Pages + SEOA Pages record per address (/about, set to Published) with an SEO record beside it: title, description, keywords, canonical, robots, share image, Open Graph and X cards, structured data.
Site setup → SEO (defaults)Site name, default title and description, default share image. These only fill tags a page doesn't have.
The head answer
/site/head?path=		One page's SEO by its address, as JSON or (format=html) as ready <head> tags. Every way of connecting uses this one answer, so they all show the same SEO. Cached for 60 seconds.
track.jsMint's script. It counts page views, clicks, visitors and journeys, loads the tags set in Site setup → Tracking (GA4, Tag Manager, Meta, TikTok, LinkedIn, Clarity, Hotjar, verification tags…) and, with data-seo, applies the head answer.
mint-edgeA Cloudflare Worker that runs in your own Cloudflare account, in front of the site. It writes the SEO into the HTML the server sends, serves Mint's script from the site's own domain, and can answer robots.txt, sitemap.xml and redirects.

The one rule: only pages you add are Mint's

If a page is added to Website → SEO, its SEO comes from Mint. If it isn't, the page keeps its own SEO, and Mint changes nothing on it (not even the defaults). A site that already has decent SEO isn't touched until you choose a page.

On a page you add, each tag is one of two kinds:

  • Set: a field you filled in for that page. It replaces the page's own tag. Mint never adds a second title or description.
  • Fill: a default from Site setup → SEO. It is used only where the page has no tag of its own.

A field you leave empty keeps the page's own value. /about, /about/, /about.html and /about/index.html are the same page.

Analytics

Both ways give full analytics: page views, clicks and custom events, visitors and their journeys (which pages, in what order), channels and sources, country, ISP, and the Live tab. Whether the visitor's IP is kept in full, masked or not at all is set in Site setup → Tracking. Ad and analytics tags set in that tab come in through Mint's script, so you don't paste their code as well.

Behind the Worker the script is served from the site's own domain (/_mint/track.js). Ad blockers block that less often than a script from another domain, so fewer visits are missed.

What the snippet can't do. A script can't pre-render. It changes the page after it loads in a browser. That's enough for Google's main index, but not for link previews or most other crawlers. If shared links matter, use the Worker (or the server print).

3. Way 1: the head snippet code: one line

  1. Paste the snippet into the <head> of every page, as high as the site lets you. Leave out defer on SEO sites so Google's renderer sees the tags early. 
    <script src="https://MINT_API/public/track.js" data-key="mint_pk_xxxx" data-seo></script>
    Analytics only? Drop data-seo; defer is fine then.
  2. Add the pages Mint should handle. In Website → Pages add the address as it shows in the browser (/menu) and set it to Published. Then give it SEO in Website → SEO. Every other page stays as it is.
  3. Fill the defaults in Site setup → SEO: site name, default share image. They only fill gaps on pages you added.
  4. Add your domain in Analytics → Domains (www and the bare domain), so visits are counted for this site only.
  5. Test the connection in Website setup → Existing website → Test connection (see section 9).

What the snippet does on each page view

  • Sends the page view (and later clicks and events) to Mint.
  • Asks the head answer for the current address. If the page isn't added ("found": false) it leaves the page alone.
  • If it is added, it replaces the set tags, creates the fill tags the page lacks, and adds structured data (JSON-LD).
  • On a single-page app it does this again on every client-side page change, and puts back the page's own values it replaced, unless the site has changed them since.

5. Server print for link previews code: a developer

If the site has a server you can edit, print the same tags in the HTML it sends. The head answer is empty for pages you haven't added, so the site's own tags stay. Keep the snippet in the page too: it counts the visits.

PHP (cPanel, custom PHP)

// mint-seo.php — this page's SEO from Mint, or '' when the page isn't added there
function mint_seo() {
  $path = parse_url($_SERVER['REQUEST_URI'], PHP_URL_PATH);
  $url  = 'https://MINT_API/public/api/site/head?format=html&apiKey=mint_pk_xxxx&path=' . urlencode($path);
  $html = @file_get_contents($url, false, stream_context_create(['http' => ['timeout' => 2]]));
  return $html ?: '';
}
// in <head>:  <?php $seo = mint_seo(); echo $seo ?: '<title>Your own title</title>'; ?>

Node / Express

const cache = new Map();
export async function mintSeo(path) {
  const hit = cache.get(path);
  if (hit && hit.until > Date.now()) return hit.html;
  const url = 'https://MINT_API/public/api/site/head?format=html&apiKey=mint_pk_xxxx&path=' + encodeURIComponent(path);
  const html = await fetch(url, { signal: AbortSignal.timeout(2000) }).then(r => (r.ok ? r.text() : '')).catch(() => '');
  cache.set(path, { html, until: Date.now() + 60_000 });
  return html;
}
// in the template's <head>:  <%- mintSeo || '<title>Your own title</title>' %>

Next.js (App Router)

async function mintSeo(path: string) {
  const url = `${process.env.MINT_API}/site/head?apiKey=${process.env.MINT_API_KEY}&path=${encodeURIComponent(path)}`;
  const h = await fetch(url, { next: { revalidate: 60 } }).then(r => (r.ok ? r.json() : null)).catch(() => null);
  return h?.found ? h.seo : null;
}
export async function generateMetadata() {
  const s = await mintSeo('/menu');
  if (!s) return { title: 'Your own title' };
  return { title: { absolute: s.title }, description: s.description,
           openGraph: { title: s.ogTitle, description: s.ogDescription, images: s.image ? [s.image] : [] } };
}

Website setup → Existing website has these with your values filled in, plus the full Next.js version (canonical, robots, X cards).

6. Way 2: Cloudflare, no code Cloudflare dashboard

For owners who can't or don't want to touch the site. Nothing on the site changes. The Worker runs in your own Cloudflare account, on your own domain, and you can switch it off at any time. Cloudflare's free Workers plan covers 100,000 requests a day; busier sites pay Cloudflare $5 a month directly.

Why Cloudflare and not a DNS record? A DNS record only says which server answers. It can't change what's in the page. Something has to sit between the visitor and the server and rewrite the HTML. On Cloudflare, that's a Worker on your domain.

Part A: put the domain on Cloudflare (skip if it already is)

  1. Sign up at dash.cloudflare.com and choose Add a domain. Enter acme.com, pick the Free plan.
  2. Cloudflare copies your DNS records. Check they match what your registrar has (especially email MX records), then continue.
  3. At your registrar (Namecheap, GoDaddy, the hosting company…), replace the nameservers with the two Cloudflare gives you. It can take from minutes to a day. Cloudflare emails you when the domain is active.
  4. In DNS → Records, make sure the records for acme.com and www are Proxied (orange cloud). A grey cloud means traffic skips Cloudflare and the Worker never runs.
  5. In SSL/TLS → Overview, set the mode to Full (strict) (or Full if the host has no valid certificate). Flexible often causes an endless redirect loop on hosts that force HTTPS.

Part B: add the Mint Worker

  1. Go to Compute (Workers) → Workers & Pages → Create → Worker. Name it mint-edge, start from "Hello World", and press Deploy.
  2. Press Edit code. Delete what's there and paste the mint-edge code Mint gives you (Website setup → Cloudflare). Press Deploy. You only paste it; you don't change anything in it.
  3. Open the Worker's Settings → Variables and Secrets and add:
    NameTypeValue
    MINT_KEYTextYour project key, mint_pk_xxxx (required)
    MINT_APITexthttps://MINT_API/public/api (only if Mint tells you to change it)
    BYPASS_SECRETSecretOptional. Any long random text, for Mint's before/after check
  4. Open Settings → Domains & Routes → Add → Route. Pick the zone acme.com and add two routes: www.acme.com/* and acme.com/*. Set Failure mode to Fail open (proceed), so if the free plan's daily limit is ever reached, visitors still reach the site.
  5. In Mint → Analytics → Domains, add acme.com and www.acme.com. The Worker only rewrites hosts the project names; any other host passes through untouched.
  6. Add the pages Mint should handle in Website → Pages and Website → SEO, exactly as in way 1. Remove the head snippet from the site if it was there: the Worker adds its own.

What the Worker does to each request

RequestWhat happens
An HTML page (GET, status 200)Fetched from your server as usual. If the page is added to SEO, Mint's tags replace or fill the head, with JSON-LD. Every page gets <script src="/_mint/track.js" …> before </body>, unless the snippet is already there.
/_mint/track.js, /_mint/api/…Passed on to Mint from your own domain. Page views carry the visitor's real address.
A redirect from Site setup → RedirectsAnswered with a 301 or 302, keeping the query string.
/robots.txt, /sitemap.xmlFrom Mint only when that's switched on; your site's own otherwise.
Images, CSS, JS, form posts, errors, anything elseUntouched. Cookies, caching headers and status codes pass through as they are.

It never breaks the site. Settings from Mint are kept for a minute and reused for up to a day. If Mint is slow (over 1 second with nothing kept) or down, the page passes through untouched. Bypass in Mint, a host the project doesn't name, or no MINT_KEY also mean "pass through". To switch it off yourself, delete the two routes in Cloudflare.

8. Worked example: a bakery site

Acme Bakery runs WordPress on shared hosting at www.acmebakery.com. The owner wants a proper title and share image on the menu page, and visitor numbers.

With the head snippet

  1. WPCode → Header: paste the snippet.
  2. Website → Pages: add /menu, Published.
  3. Website → SEO for /menu: title "Menu: fresh bread & cakes | Acme Bakery", a description, a 1200×630 share image.
  4. Analytics → Domains: add both hosts.
  5. Test connection: snippet found, visits arriving, "/menu: put on by the snippet".

Result: Google shows the new title after its next crawl. A WhatsApp share of /menu still shows WordPress's old title.

With the Cloudflare Worker

  1. Domain on Cloudflare, records proxied, SSL Full (strict).
  2. Worker mint-edge created, code pasted, MINT_KEY added.
  3. Routes www.acmebakery.com/* and acmebakery.com/*, fail open.
  4. Same pages, SEO and domains in Mint. Snippet removed from WPCode.
  5. View source of /menu: the new title is in the HTML.

Result: Google, Bing, WhatsApp, Facebook and LinkedIn all show the new title and image. Every other page looks exactly as before.

9. Testing a connection

  • Mint → Website setup → Existing website → Test connection. Enter a page address. It checks four things: the domain is the project's, the snippet is in the page's HTML with this key and data-seo, visits are arriving, and where that page's SEO comes from (not added / put on by the snippet / already in the HTML).
  • Mint → Site setup → Link previews. Enter any address to see what Facebook, WhatsApp, LinkedIn and X will show, with the image size checked.
  • View source (not "Inspect"). With the Worker, the title from Mint must be in the source; tags it wrote carry data-mint-seo="edge". With the snippet, only "Inspect" shows them.
  • The raw answer for a page: https://MINT_API/public/api/site/head?apiKey=mint_pk_xxxx&path=/menu. "found": false means the page isn't added.
  • Facebook Sharing Debugger (developers.facebook.com/tools/debug) and LinkedIn Post Inspector: press "Scrape again" after a change, since they keep old previews.
  • Google Search Console → URL Inspection → Test live URL to see the page as Google renders it.

10. Troubleshooting

What you seeWhy, and what to do
The page's SEO doesn't changeThe page isn't added, or isn't Published. Check the raw answer for "found". The address must match what the browser shows.
A change takes a while to showThe head answer is cached for 60 seconds, and track.js for 5 minutes in the browser. Wait a minute and reload.
Google shows the new title, WhatsApp doesn'tExpected with the snippet only. Use the Worker or the server print, then re-scrape in Facebook's debugger.
Test connection says "snippet not in HTML", but visits arriveIt was added through Tag Manager or a plugin that injects it later. Analytics works; SEO is applied late.
Test connection warns about deferRemove defer from the snippet on SEO sites so the tags are applied early.
Worker: nothing changes in the sourceThe DNS record is grey-cloud (not proxied); the route pattern misses the host (add both www and bare); the host isn't in Analytics → Domains; MINT_KEY is missing; or Bypass is on.
"Too many redirects" after moving to CloudflareSSL/TLS is on Flexible. Set it to Full (strict).
Email stopped after moving DNSAn MX or TXT record wasn't copied. Add it in Cloudflare DNS (grey cloud for mail records).
Two titles in the pageShouldn't happen: Mint replaces, it doesn't add. If it does, the site writes its title after Mint's script runs (some SPAs). Use the Worker.
Visits counted from the wrong siteAdd the right domains in Analytics → Domains; until then visits from any site with the key count.
